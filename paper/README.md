# Paper

LaTeX sources of the paper and of the reports (`reports/`), plus the scripts
that generate their figures and numbers from the experiments' results. The
prose in `sections/` is written by hand. Every figure and every quoted number
is generated and traceable to a results file, or written as it is with its
source and the `% num-ok` marker.

## Build

From the repo root, with the project's `.venv` active (Windows / PowerShell,
MiKTeX with `latexmk` on the PATH):

```powershell
python paper/build.py            # figures -> numbers.tex -> main.pdf
python paper/build.py --figs     # only the figures
python paper/build.py --numbers  # only numbers.tex
python paper/build.py --pdf      # only main.pdf
python paper/build.py --report e1          # the E1 report: its figures -> numbers.tex -> reports/e1_report.pdf
python paper/build.py --report e3          # the E3 report: its figures -> numbers.tex -> reports/e3_report.pdf
python paper/build.py --report e3 --pdf    # (--figs / --numbers / --pdf select steps of the report too)
python paper/check_sources.py    # source / hard-coded-number / \todo report (sections and reports)
```

`build.py` stops at the first failing step and prints its output. The figure
and number scripts read results read-only and never run an experiment. A
missing source file stops them with an explicit message, and there is no
fallback value.

`figures/out/*.pdf` and `numbers.tex` are versioned, so `--pdf` alone
compiles the paper or a report without the raw results. Some of those results
are not versioned: for example, `results/E2_online_4zones_sweep/**/per_state.csv`
is git-ignored, and so are the E3 archives extracted for the report (see
below). `main.pdf`, `reports/*.pdf` and the LaTeX auxiliary files are not
versioned.

A report owns the figure scripts matching its pattern (`build.py`, `REPORTS`:
`fig_e1_*.py` and `fig_e3_*.py` for the E1 and E3 reports); the paper's
build runs every other `fig_*.py`. `numbers.tex` is shared: the paper's build
regenerates the E1 and E3 macros too.

## Layout

```
main.tex              preamble + \input of every section
macros.tex            notation macros (\bhat, \Ihat, \Iref, \gap{X}, \Is, \pending, ...)
numbers.tex           GENERATED by numbers/gen_numbers.py -- never edit
refs.bib              bibliography (natbib, plainnat)
sections/*.tex        one file per section
reports/e1_report.tex the E1 report (standalone; \input ../macros, ../numbers)
reports/e3_report.tex the E3 report (standalone; \input ../macros, ../numbers)
figures/common.py     shared matplotlib style (size, fonts, palette, PDF export)
figures/e1_sources.py where the E1 figures and numbers read their data; recomputes with report.py's
                      filters and checks every value against E1's own etape_b_report.txt / recommendation.txt
figures/e3_sources.py where the E3 figures and numbers read their data (data access only)
figures/fig_*.py      one script per figure -> figures/out/<same name>.pdf
numbers/registry.py   Number, the readers, SourceError / PendingSource
numbers/gen_numbers.py  the E2 numbers, fmt() (the only rounding); writes numbers.tex
numbers/e1_numbers.py the E1 report's numbers
numbers/e3_numbers.py the E3 report's numbers
build.py
check_sources.py
```

## Conventions

- **`% src: <path>`**: put it on its own comment line, above any figure,
  table or statement that relies on a results file. `<path>` is relative to
  the repo root. Anything after the path (e.g. ` :: column`, or the date of
  a `docs/e3/DECISIONS.md` entry) is free text. `% src: notes` stands for the
  author's notes (`check_sources.SRC_KEYWORDS`). `check_sources.py` reports
  every `% src:` path that does not exist.
- **No hard-coded numbers in the text.** A number that comes from a result
  is a macro from `numbers.tex`. `check_sources.py` reports every digit
  outside comments, in prose and in math alike. It does not report:
  arguments of `\label`, `\ref`, `\cite...`, `\includegraphics`, `\vspace`
  and similar commands; optional `[...]` arguments; `\todo{}` content; and
  digits glued to a letter (identifiers such as `E1`). For a legitimate
  number (a definition, a section name), end the line with `% num-ok`. In a
  file with a preamble (a report), only the body is checked. A number stated
  only in `docs/e3/DECISIONS.md` or only in the notes is written as it is,
  with its `% src:` and `% num-ok`; a number with a config key or a results
  file is a macro.
- **`\pending{...}`** (macros.tex) prints an orange [pending] for a value or
  a figure of a batch that has not run yet (none at present).
  `gen_numbers.py` writes it for a `Number(..., pending=True)` whose source is
  absent, and lists it; a figure script reports itself pending by exiting
  with `e3_sources.PENDING_EXIT`, which `build.py` reports instead of failing. A source that is
  present but inconsistent always stops the build.
- **`\todo{...}`** (todonotes) marks something still to do.
  `check_sources.py` lists every remaining one.
- **Number macros**: letters only, because LaTeX macro names cannot contain
  digits. They start with the experiment spelled out (`eOne`, `eTwo`,
  `eThree`, ...), followed by the quantity in CamelCase. Examples:
  `\eTwoGapExponent`, `\eTwoGapExponentCILow`, `\eTwoNSeeds`, `\eThreeKs`.
  E3-0 is `\EThreeZero` in the text and `eThreeZero...` in macro names.
- **Figures**: `figures/fig_<exp>_<name>.py` writes
  `figures/out/fig_<exp>_<name>.pdf`, included as
  `\includegraphics{fig_<exp>_<name>.pdf}` (`\graphicspath` points to
  `figures/out/`).
- **Notation**: always use the macros from `macros.tex` (`\bhat`, `\Ihat`,
  `\Iref`, `\Istar`, `\That`, `\Ptrue`, `\Pref`, `\regret`, `\Lone`,
  `\Vstar`, `\Vpihat`, `\counts`, `\MI{a}{s'}{s}`, `\gap{X}`). Never retype
  a symbol by hand. `\regret` is the value loss Δ. The paired
  online − matched difference is `\gap{X}`, never Δ.

## Adding a figure

1. Create `figures/fig_<exp>_<name>.py`. Call `common.apply_style()`, size
   the figure with `common.figure(...)`, and save it with
   `common.save_pdf(fig, "fig_<exp>_<name>")`.
2. Read the results read-only, and check that each file exists
   (`common.require_file`). Do not write new analysis logic: import the
   experiment's own analysis functions. E2's modules use bare imports, so
   add `experiments/E2_online_4zones` to `sys.path`, as `fig_e2_gap.py`
   does. When an aggregate CSV of the same quantity already exists,
   check your recomputation against it and stop if they differ.
   Some E3 result paths exceed the Windows 260-character limit: open files
   through `common.long_path` (the `e3_sources` readers do).
3. `build.py --figs` picks up every `fig_*.py` automatically (a report's own
   scripts with `--report`).
4. Include the figure in a section, with a `% src:` comment above it.
5. Data from the closed-loop pilot is labelled "pilot data" (with its seeds)
   in the caption.

## Adding a number

1. Add one `Number(...)` entry (`numbers/registry.py`) to `E2_NUMBERS` in
   `numbers/gen_numbers.py`, or to `NUMBERS` in `numbers/e1_numbers.py` or
   `numbers/e3_numbers.py`. It
   has: the macro name, the source string (written as `% src:` above the
   macro), a getter (`one_value`, `constant_value`, `n_distinct` on a CSV;
   `key(config, "a.b")` on a YAML config; or a read of a results file), the
   number of decimals, whether to always print the sign, a style (`fixed`,
   `percent`, `sci`, `rounded`) and whether it is `pending`. Rounding is
   done only by `fmt()`.
2. Run `python paper/build.py --numbers`, check the diff of `numbers.tex`,
   and use the macro in the text.

## The E1 report (`reports/e1_report.tex`)

A translation of the author's notes (`sections/e1_notes_fr.md`) for the
supervisors, built with `python paper/build.py --report e1`. E1 is finished:
nothing is pending. Its data are E1's own artifacts, read-only
(`experiments/E1_offline_4zones/artifacts/`: `measurements.csv`,
`permutation_null.csv`, `calibration_report.csv`, `gradient_curves.csv`),
loaded with E1's `artifact.py` and imported through
`helplessness.experiment_loader` (E1 and E2 both have an `env.py`). The
quantities `report.py` only prints are recomputed by `figures/e1_sources.py`
with exactly `report.py`'s filters; everything `report.py` returns as a number
is called from it. Every recomputed value is then searched, formatted as E1
prints it, in `artifacts/etape_b_report.txt` and `artifacts/recommendation.txt`:
a difference stops the build.

## The E3 report (`reports/e3_report.tex`)

A translation of the author's notes (`sections/e3_notes_fr.md`) for the
supervisors, built with `python paper/build.py --report e3`. Its data (all
read-only, under `results/E3_worldmodel_4zones/`; `figures/e3_sources.py`):

- E3-0 (gpu_e30b), the bridge's recomputation, the estimator comparison and
  the theme sensitivity: already in `results/`;
- the agent_mini diagnostics: `reports/diagnostics*_<run>/` and
  `reports/gradients_vs_data_<run>/`;
- the closed-loop pilot, extracted from `handoff/` (git-ignored copies):
  `handoff/gpu_pilot_cl/*.tgz` at the repo root (the archives hold
  `results/E3_worldmodel_4zones/<run>/`); `handoff/gpu_pilot_remeasure/*.tgz`
  into `results/E3_worldmodel_4zones/gpu_pilot_remeasure/`;
  `handoff/gpu_pilot_noise/*.recomputed.tgz` into
  `results/E3_worldmodel_4zones/gpu_pilot_noise/`;
- the final campaign: the outputs of its own pipeline
  (`experiments/E3_worldmodel_4zones/campaign_report.py`), versioned in the
  repository and read as they are, never recomputed: the figures in
  `docs/e3/campaign_figures/` (included directly) and the values in
  `docs/e3/campaign_tables/analysis.json` (a copy of
  `results/E3_worldmodel_4zones/campaign/analysis.json`), read by the
  `\eThreeCampaign...` numbers and by `fig_e3_rsa_partition.py`. The numbers
  stated only in `docs/E3_worldmodel_4zones.md` (results section) or in
  `docs/e3/DECISIONS.md` are written as they are, with `% src:` and `% num-ok`.
